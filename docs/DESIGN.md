# Дизайн

Ориентир — современные TUI вроде Claude Code CLI и opencode: спокойно, минималистично, один акцентный цвет, всё управляется с клавиатуры.

Свои макеты экранов рисуй в [`mockups/`](mockups/) по шаблону [`_TEMPLATE.md`](mockups/_TEMPLATE.md).

## Принципы
1. **Тишина по умолчанию.** Рамки и второстепенный текст приглушённые (серые). Яркое только то, что важно сейчас.
2. **Один акцент.** Акцентным цветом выделяются фокус, выбранная строка и курсор ввода. Остальные цвета только смысловые (добавлено, удалено, ошибка).
3. **Фокус виден по рамке.** У активной панели рамка акцентного цвета, у остальных — muted.
4. **Скруглённые углы** `╭╮╰╯` у всех рамок (`LineStyle.Rounded`).
5. **Подсказки всегда на экране.** Нижняя строка показывает клавиши для текущей панели.
6. **Прозрачность.** Перед любым действием можно увидеть git-команду, после — результат в Command Log.
7. **Обратная связь как в Claude CLI:** спиннер с глаголом во время работы, `✓` / `✗` по завершении.
8. **Работает в 80×24.** На узком экране панели складываются, ничего не обрезается без `…`.
9. **Фон терминала не трогаем** — используем фон пользователя, чтобы тема терминала оставалась его.

## Палитра (токены)

Все цвета в коде берутся только из `Theme`. Палитра основана на стандартной теме Neovim: блёклые синий и зелёный.

| Токен        | Цвет      | Где используется                                   |
|--------------|-----------|----------------------------------------------------|
| `fg`         | по умолч. | основной текст                                     |
| `muted`      | `#9B9EA4` | подсказки, второстепенный текст                    |
| `dim`        | `#4F5258` | версия, блики на волнах, рамки без фокуса          |
| `accent`     | `#A6DBFF` | рамка в фокусе, `❯`, курсор, кнопка в фокусе       |
| `green`      | `#B3F6C0` | второй цвет градиентов (логотип, волны)            |
| `selectionBg`| `#2C2E33` | фон выбранной строки                               |
| `success`    | `#B3F6C0` | `✓`, staged, `+` в diff, авторизованный пользователь |
| `error`      | `#FFC0B9` | `✗`, `-` в diff, ошибки                            |
| `warning`    | `#FCE094` | `▲`, modified, «Не авторизован»                    |
| `info`       | `#8CF8F7` | ветки, `@@` в diff                                 |
| `backdrop`   | `#14161B` | предполагаемый фон терминала для приглушения цветов |

## Подсветка синтаксиса (diff)
C# подсвечивается через Roslyn (синтаксическое дерево, без компиляции). Цвета — тёмная тема Visual Studio:

| Токен | Цвет | Примеры |
|---|---|---|
| ключевое слово | `#569CD6` | `public`, `class`, `var`, `null` |
| управляющее слово | `#D8A0DF` | `if`, `return`, `foreach`, `try` |
| класс, record | `#4EC9B0` | `Console`, `List<T>` |
| struct | `#86C691` | `record struct Point` |
| интерфейс, enum, параметр типа | `#B8D7A3` | `IRunner`, `T` |
| метод | `#DCDCAA` | `WriteLine()` |
| параметр, локальная переменная | `#9CDCFE` | `args`, `total` |
| строка, символ | `#D69D85` | `"text"`, `'x'` |
| число | `#B5CEA8` | `42` |
| комментарий | `#57A64A` | `// …`, `/// <summary>` |
| препроцессор | `#9B9B9B` | `#if DEBUG` |
| остальное | `#DCDCDC` | |

Фон строк `+`/`-` (`AddedBg` / `RemovedBg`) сохраняется, подсветка меняет только цвет текста.

## Декорации
Анимации работают от общего таймера (`AnimatedView`, ≈12 кадров/с) и никогда не рисуются поверх элементов интерфейса.

- **Логотип** — вертикальный градиент `accent → green`.
- **Волны** — 5 нижних строк над подсказками. Цвет переливается между `accent` и `green`, приглушён к `backdrop`, гребень ярче глубины, над гребнями изредка блики `·`. Не рисуются, если окно ниже 26 строк.
- **Звёздное небо** — фон над волнами. Звёзды мерцают; у краёв экрана они ярче, крупнее (`• ⋆ ✧`) и примерно вдвое чаще, центр остаётся спокойным.
- **Падающие звёзды** — раз в 4–11 с появляются сбоку и летят от центра наружу, хвост `─ ·` гаснет.
- **Значок C#** — неподвижный, в левом верхнем углу стартового экрана. Шестиугольник 20×11 символов с вертикальными боковыми сторонами, три грани разной яркости (градиент `accent → green`), кольцо «C» и знак «#». Рисуется полублоками `▀▄`. Не рисуется в окне меньше 90×24.
- **Версия** `LGit vX.Y.Z` — цветом `dim` в правом нижнем углу.
- **Маскот** — маленький значок 13×7 символов (полублоки) в правом нижнем углу панели diff: Clawd — краб-маскот Claude Code (оранжевый, `#D97757`), ChatGPT (зелёная надпись GPT пиксельным шрифтом, `#10A37F`), Gemini (четырёхлучевая звезда, градиент `#4796E3 → #9177C7 → #CA6673`) или никого (по умолчанию). Выбирается в окне настроек (`,`), сохраняется в конфиг. Рисуется, только если diff до него не доходит (с пустой строкой зазора) и панель шире 43 символов — текст никогда не закрывает.

```
╭─ Настройки ────────────────────────────────╮
│ Маскот в углу diff                         │
│                                            │
│   Нет                                      │
│   Clawd                     ▄▄▄ ▄▄▄  ▄▄▄   │
│ ❯ ChatGPT                  ▀    ▀  ▀  ▀    │
│   Gemini                   ▀ ▄▄ ▀▄▄▀  ▀    │
│                            ▀  ▀ ▀     ▀    │
│                            ▀▄▄▀ ▀     ▀    │
╰────────────────────────────────────────────╯
 ↑↓ выбор · enter сохранить · esc отмена
```

## Плашки
- **Плашка** (`Segment.Badge`) — тёмная буква на цветном фоне. Показывает вид изменения файла, как в VS Code и Rider:

| Плашка | Значение | Цвет |
|---|---|---|
| ` M ` | изменён | `warning` |
| ` A ` | добавлен | `success` |
| ` D ` | удалён | `error` |
| ` R ` / ` C ` | переименован / скопирован | `info` |
| ` T ` | сменился тип файла | `warning` |
| ` U ` | новый файл (untracked) | `cyan` |
| ` ! ` | конфликт | `error` |

- **Мягкая плашка** (`Segment.Pill`) — цветной текст на приглушённом фоне того же цвета (`Theme.Tint`). Используется для заголовков разделов (` Staged `, ` Изменения `, ` Новые файлы `), ветки (` ⎇ main `), счётчика изменений и пользователя (` ● login `).

## Символы

| Символ | Значение                  | Символ | Значение            |
|--------|---------------------------|--------|---------------------|
| `❯`    | выбранная строка          | `✓`    | успех               |
| `●`    | авторизован               | `✗`    | ошибка              |
| `○`    | не авторизован            | `▲`    | предупреждение      |
| `⎇`    | ветка                     | `↑2`   | впереди upstream    |
| `→`    | переименование `old → new` | `↓1`  | позади upstream     |
| `…`    | обрезанный текст          | `·`    | разделитель подсказок |
| `⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏` | кадры спиннера    |        |                     |


- Левая колонка ≈ 35% ширины, правая — остальное.
- Номера `[1]`–`[3]` в заголовках = клавиши быстрого перехода.
- Правая панель показывает контекст выбранного: diff файла, лог ветки, изменения коммита.
- Файлы внутри раздела показаны деревом: сначала папки (имя жирным основным цветом; `▾` развёрнута, `▸` свёрнута, стрелка `muted`; у свёрнутой — число файлов), потом файлы, отступ 3 символа на уровень с направляющей `│` цвета `dim` под стрелкой родительской папки. Цепочка папок с единственной вложенной папкой показывается одной строкой: `LazyGit/UI/Panels/`. `enter` сворачивает и разворачивает папку, `←` / `h` сворачивает её или переходит к родительской папке, `→` / `l` разворачивает. `space` на папке — stage / unstage всех её файлов в этом разделе.
- Рамка и заголовок панели в фокусе — `accent`, остальных — `dim`. `tab` / `shift+tab` переключают панели.
- Строка коммита: граф, короткий хеш (`muted`), ветки и теги, заголовок, справа давность (`dim`: «5 мин», «3 ч», «2 дн», «4 нед»). На панели уже 30 символов давность скрывается.
- Граф: коммит `●`, merge `◉`, каждая дорожка — два символа, линии `│ ─ ╮ ╯ ╭ ╰ ┤ ├ ┼`. Цвет закреплён за веткой (по кругу: `accent`, `cyan`, `green`, `warning`, `syntaxControlKeyword`),
  линия текущей ветки всегда `accent` и идёт прямо: другие ветки вливаются в неё.
  Граф шире трети строки обрезается с `…`. Лог в порядке `--topo-order`, строка графа всегда совпадает со строкой коммита.
- Метки (в этом порядке): текущая ветка `⎇ main` (`info` жирным) или detached `HEAD`, другие локальные `⎇ feature` (`green`), удалённые `origin/main` (`muted`), теги `#v1.0` (`warning`).

## Граф всех веток (`G`)
Полноэкранное окно, как Git Graph в Visual Studio: сверху граф всех локальных и удалённых веток и тегов
(последние 1000 коммитов, с колонкой автора), снизу выбранный коммит — как в панели коммитов. Внизу строка статуса и подсказки.

```
╭─ Граф · все ветки ───────────────────────────────────────────────────────────────╮
│   ● cb18816 ⎇ bugfix/crash fix crash                          Даниил      2 ч    │
│ ❯ │ ● ac6e918 ⎇ main origin/main main: docs                   Даниил      3 ч    │
│   │ │ ● e0e00cf origin/feature/graph graph: lanes             Даниил      3 ч    │
│   │ ◉─┤ 5f5cec1 Merge feature/login                           Даниил      4 ч    │
│   ╰─● │ 9db9f30 main: config                                  Даниил      5 ч    │
╰──────────────────────────────────────────────────────────────────────────────────╯
╭─ Коммит · ac6e918 ───────────────────────────────────────────────────────────────╮
│ ac6e918 · Даниил · 01.11.2026 16:09 (3 ч назад)                                  │
╰──────────────────────────────────────────────────────────────────────────────────╯
 space checkout · n ветка отсюда · t тег · M merge · C cherry-pick · v revert · y хеш · esc закрыть
```

| Клавиша | Действие |
|---|---|
| `space` / `enter` | checkout: локальная ветка на коммите → переключение; только удалённая → новая локальная ветка, следящая за ней (или существующая с тем же именем); без веток → detached HEAD после подтверждения |
| `n` | новая ветка от коммита и переключение на неё |
| `t` | лёгкий тег на коммит |
| `M` | merge в текущую: ветка с коммита (локальная, иначе удалённая) или сам коммит |
| `C` / `v` | cherry-pick / revert (с подтверждением) |
| `y` | скопировать полный хеш |
| `ctrl+d` / `ctrl+u`, `r` | листать коммит, перечитать граф |

Действия выполняются сразу, итог — в строке статуса окна; после закрытия главное окно обновляется.

```
│ ❯ ◉─╮ 40085bc ⎇ main Merge branch 'feature'   1 ч │
│   │ ● 4489194 origin/feature feat: help layout 1 ч │
│   ● │ 5d93686 #v1.0 feat: gitignore download     2 ч │
│   ●─╯ 212a234 init                             3 ч │
```
- Когда в фокусе коммиты, справа показан выбранный коммит: строка «хеш · автор · дата (давность)» цветом `muted`, сообщение (заголовок жирным), затем diff каждого файла под полосой с путём на фоне `selectionBg`. Merge-коммит показывается относительно первого родителя.

```
╭─ Коммит · 6ac963a ─────────────────────────────────────╮
│ 6ac963a · DaniilMedvin · 31.10.2026 22:57 (8 мин назад) │
│ feat: add indent guides to the files tree               │
│                                                         │
│ LazyGit/UI/Panels/FilesPanel.cs                         │
│ @@ -165,7 +165,8 @@ public sealed class FilesPanel      │
│ 168     -     new Segment(Indent(row.Depth) + symbol…   │
│     168 +     new Segment(Indent(row.Depth), Theme.Dim) │
╰─────────────────────────────────────────────────────────╯
```
- Строка ветки: текущая отмечена `●` и выделена `info` жирным, справа `↑2` (`success`) `↓1` (`warning`) относительно upstream или «upstream удалён» (`dim`). После checkout выбор переходит на новую текущую ветку.
- Подсказки внизу зависят от панели в фокусе: `space stage · a все` только в файлах.

### Построчный stage
`enter` на файле переводит фокус в diff (рамка `accent`), заголовок — «Stage по строкам · путь» или для файла из Staged —
«Unstage по строкам · путь · staged». Курсор ходит только по строкам `+` / `-` (`↑↓` / `j k`, `PageUp` / `PageDown`, `Home` / `End`),
выбранная строка и выделение — фон `selectionBg` вместо фона `+` / `-`, цвет маркера сохраняется.
`space` — stage (unstage) строки или выделения, `v` — начать / снять выделение, `a` — весь фрагмент `@@`, `esc` — к файлам.
`d` — сбросить строки в рабочей копии (только не staged часть, через подтверждение). `tab` — к другой части того же файла
(staged ↔ изменения), если она есть; подсказка называет, куда переход: `tab staged` или `tab изменения`.
Когда в этой стороне файла изменений не осталось, фокус сам возвращается к файлам.

```
 space stage · a фрагмент · v выделить · d сбросить · tab staged · esc к файлам · c коммит · ? справка · q выход
```

## Диалог коммита
Похож на поле ввода Claude CLI: одна рамка, приглашение `>`, подсказки под ней.
Тип выбирается `tab` / `shift+tab`, выбранный выделен фоном `accent`. Если текст уже начинается с типа (`fix(ui): …`), он не дублируется.
Под заголовком — итоговый заголовок и счётчик (`dim` до 50, `warning` до 72, `error` больше 72), ниже — самая важная подсказка:
длина, английский язык, повелительное наклонение (`add`, а не `added`), строчная буква после типа, точка в конце, длинные строки тела.

Тело необязательно. `↓` из заголовка — в тело, `↑` на первой строке тела — обратно. В заголовке `enter` сразу коммитит,
в теле `enter` — новая строка, коммит — `ctrl+s`. Пустая строка между заголовком и телом добавляется автоматически.
Подсказки внизу зависят от поля, в котором курсор.

```
╭─ Коммит ─────────────────────────────────────────────────────────────╮
│  feat   fix   docs   refactor   test   chore   style   без типа      │
│                                                                      │
│ > update binary image                                                │
│                                                                      │
│ feat: update binary image                                      25/72 │
│ ▲ Строка 2 тела длиннее 72 символов — перенеси её                    │
│                                                                      │
│ Тело коммита · 2 строки                                              │
│ │ - replace img.bin with a new version                               │
│ │ - keep the old file name and format for compatibility with         │
│ │ existing scripts                                                   │
│ │                                                                    │
│                                                                      │
│ Staged: 1 файл                                                       │
╰──────────────────────────────────────────────────────────────────────╯
 ctrl+s коммит · enter строка · ↑ заголовок · tab тип · esc отмена
```

Поля ввода (`ClipboardTextField`, `ClipboardTextView`) работают с системным буфером обмена: `ctrl+c` — копировать (без выделения — всё поле), `ctrl+x` — вырезать, `ctrl+v` — вставить, `ctrl+a` — выделить всё. Буфер — через `wl-copy`/`wl-paste`, `xsel`/`xclip`, `pbcopy`/`pbpaste`.

### Шаблоны коммита (`ctrl+t`)
В окне коммита `ctrl+t` открывает список заготовок: тип, начало заголовка и тело. Под списком — заголовок, который получится.
`enter` подставляет шаблон, курсор встаёт в конец заголовка — остаётся дописать суть. Шаблоны: новая функция, исправление бага
(тело «Причина / Исправление»), опечатка, рефакторинг, тесты, документация, зависимости, ломающее изменение
(`feat!:` + `BREAKING CHANGE:`), первый коммит, добавить README, добавить .gitignore, wip.

## Быстрые файлы репозитория
`R` создаёт `README.md` (заголовок — имя папки), `I` — `.gitignore` со стандартными правилами Visual Studio.
`.gitignore` скачивается с GitHub (`github/gitignore`, `VisualStudio.gitignore`), поэтому правила всегда актуальны; в конец добавляются
свои (`.env*`, `.idea/`), если шаблона их нет. Без сети (таймаут 8 с) берётся встроенная копия, и строка статуса предупреждает об этом.
Существующие файлы не перезаписываются: команда в этом случае недоступна. После создания файл виден в «Новых файлах»,
а в окне коммита есть шаблоны «Добавить README» и «Добавить .gitignore».

## Новая ветка
`n` в панели веток. Ветка создаётся от текущего HEAD, после создания на неё сразу выполняется переключение.
Имя проверяется по правилам git при вводе, подсказка `warning` объясняет, что не так. Пустое имя — ошибка только при `enter`.

```
╭─ Новая ветка ────────────────────────────────────────────╮
│ > my branch                                              │
│                                                          │
│ От: feature/diff · 8e77301                               │
│                                                          │
│ ▲ Пробелы нельзя: используй - или /                      │
╰──────────────────────────────────────────────────────────╯
 enter создать и переключиться · esc отмена
```

## Подтверждение опасного действия
Рамка цвета `warning`, обязательно показываем точную команду. Фокус по умолчанию на «Отмена».
`← →` / `tab` — выбор кнопки, `enter` — нажать, `esc` — отмена. Длинное предупреждение переносится по словам.

Удаление ветки (`D`): сначала `git branch -d`. Если в ветке есть невлитые коммиты, git отказывает,
и второе подтверждение предлагает `git branch -D` с числом коммитов, которые пропадут.

```
╭─ ▲ Опасное действие ─────────────────────────────────────╮
│ Сбросить все изменения в Program.cs?                     │
│                                                          │
│ Будет выполнено:                                         │
│   git restore -- Program.cs                              │
│                                                          │
│ Это нельзя отменить.                                     │
│                                                          │
│        [ Отмена ]      [ Сбросить ]                      │
╰──────────────────────────────────────────────────────────╯
```

Сброс файла или папки (`d` в панели файлов) зависит от раздела: «Изменения» — `git restore` (staged-часть остаётся),
Staged — `git restore --source=HEAD --staged --worktree`, новые файлы — `git clean --force` (удаление с диска).
Конфликты так не сбрасываются. В команде пути с пробелами взяты в кавычки, больше трёх путей сокращаются: `… ещё 5`.

## Строка подсказок
Если подсказки не помещаются, сначала убираются второстепенные (`tab панель`, `p/P pull/push`, `a все`, `ctrl+g войти`) — с конца.
`? справка`, `esc назад` и `q выход` видны всегда.

## Конфликты и незавершённые операции
Если merge, cherry-pick, revert или rebase остановился (обычно на конфликте), в шапке после счётчика изменений —
мягкая плашка `warning`: ` ▲ идёт merge `. Пока она есть, работает `A` — прервать операцию (`git merge --abort` и т.п.)
с подтверждением; ветка возвращается к состоянию до операции, и `C` — продолжить (`git rebase --continue` и т.п.;
редактор не открывается, git берёт готовое сообщение). Cherry-pick (`C` в ветках и коммитах) во время операции недоступен.

На конфликтном файле или папке в разделе «Конфликты»: `o` — оставить нашу версию, `t` — их
(`git checkout --ours/--theirs`, затем `git add`), `b` — обе подряд: сначала наши строки, затем их
(`git merge-file --union` поверх нашей версии; база и их версия берутся из индекса побайтово через `checkout-index --temp`). Без подтверждения: вернуть конфликт можно `git checkout -m -- путь`,
это написано в сообщении `✓`. При rebase «наша» — ветка, на которую переносятся коммиты.
Подсказки `o наша · t их · b оба` и `A прервать` показываются, только когда эти действия доступны.

**По блокам** (`enter` на конфликтном файле): справа файл целиком вместо diff. У каждой стороны блока заголовок
`❯ Блок 1/3 · наша · HEAD` и полоса `▌` слева: наша — info, база (diff3) — muted, их — warning; текущий блок яркий
(заголовок accent), остальные приглушены, код подсвечивается. `↑↓` — к соседнему блоку, `o` / `t` / `b` — оставить
сторону в текущем блоке (файл записывается сразу, LF / CRLF и BOM сохраняются), последний блок решён — файл
добавляется в индекс и режим заканчивается. `r` — вернуть конфликт (`git checkout --merge`, с подтверждением),
`esc` — к файлам. Не UTF-8, нет маркеров или они не сходятся — объяснение и подсказка решить файл целиком.
Завершить merge: решить все конфликты, добавить файлы (`space`), сделать коммит (`c`) или нажать `C`.

## Исправить старый коммит (`F` в коммитах)
Staged-изменения встраиваются в выбранный коммит: `git commit --fixup=<хеш>`, затем `git rebase -i --autosquash
--autostash <хеш>^` (у первого коммита — `--root`) без редактора. Подтверждение показывает обе команды и сколько
коммитов пересоздастся; если они уже отправлены — предупреждение про `--force-with-lease`. Нечего встраивать,
последний коммит (для него `a` — amend), merge-коммит между целью и HEAD или незаконченная операция — объяснение.
Конфликт с более поздними коммитами — обычная остановка rebase (`C` / `A`).

## Interactive rebase
`i` в панели коммитов — план rebase от выбранного коммита (включительно) до HEAD. Коммиты новые сверху, как в логе.
Действие слева цветом: `pick` muted, `reword` info, `edit` warning, `squash` / `fixup` accent со стрелкой `↓`
(вливаются в коммит ниже), `drop` error, заголовок зачёркнут. Повторное нажатие той же клавиши возвращает `pick`.
`r` спрашивает новый заголовок, тело сообщения сохраняется. Внизу — итог плана или почему его нельзя выполнить.
После `enter` — подтверждение с командой. Диапазон с merge-коммитом не поддерживается.

Как выполняется: todo пишется в `.git/lazygit-cs-rebase/` и подставляется через `GIT_SEQUENCE_EDITOR`;
reword — `pick` + `exec git commit --amend --only --file=…`; squash берёт объединённое сообщение без редактора;
`--autostash` прячет незакоммиченные изменения. На `edit` и конфликте rebase останавливается: поправить файлы,
`a` — amend, `C` — продолжить, `A` — вернуть всё как было.

```
╭─ Interactive rebase ─────────────────────────────────────────────────╮
│ 4 коммита, новые сверху. squash / fixup вливают коммит в тот, что ниже │
│    fixup  e4ea93d ↓ feat: файл 5                                     │
│  ❯ pick   a615552 feat: файл 3                                       │
│    drop   afa84f4 feat: файл 4                                       │
│    reword 5792ec3 feat: второй файл                                  │
│                                                                      │
│ Будет: 1 reword, 1 fixup, 1 drop, порядок изменён                    │
╰──────────────────────────────────────────────────────────────────────╯
 r reword · e edit · s squash · f fixup · d drop · J/K порядок · enter выполнить · esc отмена
```

```
│ demo    ⎇ main   нет upstream    2 изменения     ▲ идёт merge    ~/demo        ● login │
 space stage · a все · o наша · t их · b оба · d сбросить · A прервать · c коммит · …
```

## Stash
`s` (везде) прячет все изменения, включая новые файлы (`git stash push --include-untracked`); сообщение необязательно.
Панель `[4] Stash` под коммитами видна, только когда stash не пуст, высота — по числу записей (не больше 5).
Строка: номер, сообщение (своё или «WIP on main: …»), давность справа. Справа — изменения stash, как у коммита.
`space` — pop (применить и удалить), `a` — apply (оставить в списке), `d` — удалить с подтверждением.
При конфликте stash не удаляется: «Конфликт в stash: реши файлы в «Конфликтах» и добавь (space), stash сохранён».

```
╭─ [4] Stash ─────────────────────╮
│ ❯ 0 wip: эксперимент     сейчас │
│   1 WIP on main: 16545f5 …  2 ч │
╰─────────────────────────────────╯
```

## Правка истории (панель коммитов и веток)
Клавиши панели `[3] Коммиты`; все действия идут через подтверждение с git-командой.

| Клавиша | Действие | Команда |
|---|---|---|
| `a` | amend: staged-изменения в последний коммит, сообщение то же | `git commit --amend --no-edit` |
| `v` | revert: новый коммит, отменяющий выбранный | `git revert --no-edit <hash>` |
| `S` / `m` / `H` | reset к выбранному: soft / mixed / hard | `git reset --soft\|--mixed\|--hard <hash>` |
| `C` | cherry-pick по хешу, сокращённому хешу или имени ветки | `git cherry-pick <hash>` |

В панели `[2] Ветки` `C` копирует вершину выбранной ветки в текущую.
Amend и reset переписывают историю: если коммиты уже в upstream, подтверждение предупреждает о `--force-with-lease`.
Конфликт revert / cherry-pick показывается в шапке (`▲ идёт revert`), решается как конфликт merge; `A` прерывает.

## Отмена последнего действия (`z`)
Смотрит последнюю запись reflog HEAD:

| Действие | Отмена | Подтверждение |
|---|---|---|
| коммит, amend | `git reset --soft HEAD@{1}` — изменения возвращаются в индекс | да |
| merge, pull, merge-коммит, cherry-pick | `git reset --keep HEAD@{1}` — незакоммиченные изменения сохраняются | да |
| checkout | `git switch` обратно (на хеш — с `--detach`) | нет |
| первый коммит, reset, rebase | не отменяется, `✗` объясняет почему | — |

Если отменяемое уже есть в upstream, предупреждение в подтверждении говорит, что для push понадобится `--force-with-lease`.
Повторное `z` после checkout возвращает обратно; после отмены коммита действие повторяется заново (`c`).

## Command Log (`~`)
Панель под diff высотой 8 строк, открывается и закрывается `~`, состояние запоминается в конфиге.
Пишутся только команды, выполненные по действиям пользователя; фоновые чтения (статус, diff, лог) — нет.
Новые команды внизу. У ошибки ниже — первая строка вывода git цветом `error`, у отменённой — `⊘` и «отменена».

```
╭─ Command Log ─────────────────────────────────────────────────╮
│ 23:59:27 ✓ git add -- 'new file.txt'                    34 мс │
│ 23:59:37 ✗ git switch --no-guess other                  17 мс │
│            error: Your local changes to the following files w…│
╰───────────────────────────────────────────────────────────────╯
```

## Статус операций (строка над подсказками)

```
 ⠹ Отправка в origin/main…  esc отмена
 ✓ Отправлено 2 коммита в origin/main
 ✗ Push отклонён: на сервере есть новые коммиты. Нажми p, чтобы сделать pull
```

Сообщение `✓` исчезает через ~3 секунды, `✗` висит до следующего действия.
Пока идёт push / pull / fetch, `esc` отменяет операцию (процесс git убивается), а не возвращает к стартовому экрану.

Push ветки без upstream — в два нажатия: первое `P` показывает
`▲ Нет upstream для main. Нажми P ещё раз, чтобы выполнить git push --set-upstream origin main`, второе выполняет её.

## Палитра команд (`ctrl+p` или `:`)
Как в opencode: нечёткий поиск по всем доступным командам (по названию, id, клавише и русским ключевым словам —
«мерж» находит Merge). Справа клавиша, опасные отмечены `▲`, рядом с названием — панель команды.
Под списком — git-команда выбранного действия цветом `info`. Навигация (tab, 1/2/3, ctrl+d/u) в палитре не показывается.
`↑↓` / `ctrl+n` `ctrl+p` — выбор, `enter` — выполнить, `esc` — закрыть.

```
╭─ Команды ────────────────────────────────────────────────────╮
│ > pu                                                         │
│                                                              │
│ ❯ Pull                                                    p  │
│   Push / push -u                                          P  │
│   Stage / unstage  файлы                              space  │
│                                                              │
│ git pull --no-edit                                           │
╰──────────────────────────────────────────────────────────────╯
 ↑↓ выбор · enter выполнить · esc закрыть
```

## Просмотр справа
- Заголовки панелей со счётчиками: `[1] Файлы · 5` (файлов), `[2] Ветки · 1/3`, `[3] Коммиты · 4/200+`
  (выбранный / всего; `+` — загружены не все), `[4] Stash · 1/2`.
- Коммит: полный хеш (muted), автор и дата, сообщение, затем сводка как `git show --stat` —
  `путь | 12 ++++----` (`+` success, `-` error, у бинарного `Bin`) и итог `2 файла изменено · +32 · -2`, ниже diff файлов.
- Ветка в фокусе: справа её `git log --graph` (как превью ветки в lazygit), но в цветах приложения и без checkout.
  Граф линиями `│ ╱ ╲` цветом дорожки, коммит `●`, merge `◉`; хеш warning; ссылки как в git, но цветом:
  `(HEAD → main, origin/main, tag: v1.0)` — HEAD info, ветки success, удалённые error, теги warning;
  строка автора: имя muted, дата fg, `(давность)` accent; тело сообщения muted. В заголовке `⎇ ветка · upstream ↑1 ↓0`.
- Колесо мыши: diff и лог ветки листаются по 3 строки, в списках колесо двигает выбор. `ctrl+d/u` — на пол-экрана.

## Стартовый экран: недавние
Под полем пути — рамка «Недавние» (до 5 существующих папок, свежие первыми): имя проекта жирным и путь dim.
`↓` из поля — в список (рамка accent, `❯` на строке), `↑` с первой строки — обратно, `enter` — открыть.
Подсказки внизу не налезают на версию в правом углу.

## История файла (`h` на файле, `F` — любой файл)
`F` открывает выбор файла: поле `>`, справа `найдено/всего`, список путей — папка dim, имя жирным; сначала файлы,
чьё имя начинается с ввода, потом с вводом в имени, потом в пути. Окно истории — как граф: сверху коммиты, менявшие
файл (через переименования, `git log --follow`): `a1b2c3d  M  заголовок  ← старое имя   автор  2 дн` — плашка
статуса цветом как у файлов (A success, M warning, D error, R info). Снизу выбранный коммит с diff только этого файла
(у переименования — со старым именем); `a` — весь коммит / только файл, `y` — хеш, `ctrl+d/u` — листать.

## Blame (`B` на файле, `b` в истории файла)
Сверху строки файла: `a1b2c3d автор         2 нед │  12 │ код` — подпись коммита только у первой из подряд идущих строк
одного коммита (хеш warning, автор muted), остальные строки группы связаны с ней линией `│` под хешем, у последней — `└`;
код подсвечен. Строки того же коммита, что и выбранная, отмечены accent
(хеш и `│`) — видно, что ещё поменял этот коммит. Незакоммиченные строки — «не закоммичено». Снизу коммит выбранной
строки с diff этого файла (`a` — весь коммит). `p` — blame в родителе коммита строки (кто написал её раньше; имя файла —
каким было тогда), `esc` — шаг назад с возвратом на ту же строку, на последнем шаге — закрыть. В строке статуса
`33 строки · 3 коммита · шаг назад: 1 (esc)`.

## Сравнение (`=` на ветке, коммите или в графе)
Сверху `⎇ main ↔ ⎇ feature   от общего предка a1b2c3d   только в feature: 5 · только в main: 2` — левая сторона
плашкой info, правая accent, «только в правой» success, «только в левой» warning (если не 0). Вкладки
`1 Файлы 3  2 Коммиты 5` (текущая — плашкой). Файлы: плашка статуса, у переименования `старое → новое`, справа
`+12` success `-3` error (бинарный — `Bin`). Коммиты — только во второй стороне, как в панели коммитов. Снизу diff
выбранного файла (с подсветкой) или коммита. `m` — от общего предка (`main...feature`, что принесёт ветка, как в PR;
по умолчанию) / между вершинами (`main..feature`), `s` — поменять стороны.

## Поиск по истории (`ctrl+f`)
Сверху поле `>` и режимы `[Сообщение]  Автор  Код` (текущий — плашкой accent, `tab` — следующий), справа «в текущей
ветке» dim или «во всех ветках» info (`ctrl+a`). Поиск идёт сам через 350 мс после ввода, незаконченный отменяется
(процесс git убивается). Текст ищется как есть, без учёта регистра; «Код» — коммиты, где строка появилась или исчезла
(`git log -S`). Ниже коммиты без графа (коммиты не подряд) с автором и давностью, снизу выбранный коммит.
Пустой список подсказывает, что вводить в текущем режиме. `↑↓` — коммит, `ctrl+y` — хеш, `ctrl+d/u` — листать.

## Подробнее о коде (`ctrl+e`)
По умолчанию выключено. Включено — над diff файла, коммита или stash блок «Что изменилось в коде»: по каждому C#-файлу
(путь — если файлов несколько) строки `+ метод   Cache.LoadAsync(string)` — `+` success, `~` warning (изменён),
`−` error (удалён, имя muted); вид (класс, record, метод, свойство, поле, конструктор…) muted. В коммите блок стоит
перед сводкой файлов. Новый или удалённый тип — одной строкой, без каждого его члена; перегрузки различаются по типам
параметров; правка только форматирования или комментариев изменением не считается. Изменений нет — строка-пояснение.

## Сообщение по коду (`ctrl+e` в окне коммита)
По запросу: смотрит изменённые классы и методы в staged C#-файлах (HEAD против индекса). Заголовок и тип — только если
заголовок пуст (набранное не стирается): одно изменение — `add Cache.LoadAsync`, два в одном типе одного вида —
`update Client.Load and Save`, несколько в одном типе — `update Cache`, в разных — `update A, B` или `update 3 files`;
тип `test` (только тесты), `feat` (есть добавленное) или `refactor`. В тело дописывается список `- add …`, `- update …`,
`- remove …` (до 15 строк). Глаголы английские при любом языке интерфейса: так принято в Conventional Commits.
Подсказка под заголовком: «Заполнено по изменённому коду — поправь под себя»; изменений нет — предупреждение.

## Теги (`#`)
Полноэкранное окно: сверху теги, свежие первыми — `#v1.0` warning жирным, короткий хеш muted, у аннотированного `✎`
info перед сообщением, у лёгкого — заголовок коммита, справа давность. Снизу коммит тега. `n` — тег на HEAD: имя,
затем сообщение (с ним тег аннотированный), `P` — отправить (`git push origin refs/tags/…`), `D` — выбор «только
здесь» / «здесь и в origin» и подтверждение с командой, `y` — имя.

## Мелочи веток, stash и операций
- `R` в ветках — переименовать: поле с текущим именем (выделено, ввод заменяет), проверка как у новой ветки,
  если есть upstream — пояснение, что ветка на сервере не переименуется.
- `S` в файлах — stash только файла или папки под курсором (новые файлы тоже), остальное на месте.
- `K` во время rebase / cherry-pick / revert — пропустить текущий коммит (с подтверждением), рядом с `C` и `A`.
- Панель коммитов: выбор в 5 строках от конца загруженного лога — подгружаются ещё 200; в заголовке `200/400+`.

## GitHub (`g`)
Полноэкранное окно, как граф. Сверху вкладки `1 Этот репозиторий 53   2 Мои PR   3 Ждут меня` (текущая — плашкой accent),
ниже список PR: `#12 ✓ ● заголовок … автор  2 дн` — первый значок CI (`✓` success, `✗` error, `●` warning — идёт),
второй — ревью (`✓` одобрен, `✗` просят правки, `●` ждёт), черновик приглушён. Во вкладках по всем репозиториям —
`LazyGit#12`. Снизу выбранный PR: `репо#12 · ветка → main · автор · давность`, состояние (`✓ CI · ● ждёт ревью · ✗ конфликт`),
заголовок, описание (комментарии шаблона `<!-- -->` скрыты), проверки CI (упавшие первыми), сводка файлов и diff.
Merge — выбор способа (Squash / Merge commit / Rebase) и подтверждение с предупреждениями о CI, ревью и черновике.
Новый PR (`N`) — окно как у коммита: `⎇ ветка → main · 2 коммита`, заголовок, описание Markdown, `ctrl+d` — черновик.
`/` — выбор репозитория: поле поиска `>`, ниже недавние локальные (справа путь копии цветом success), затем свои
репозитории с GitHub (`GitHub` / `GitHub · приватный` dim); введённый `владелец/репо`, которого нет в списке, —
первой строкой «ввести вручную». Выбранный — вкладка `4 владелец/репо` со всеми его открытыми PR (одна, заменяется).

`enter` на PR другого проекта открывает его локальную копию (ищется по remote среди недавних репозиториев) или,
если её нет, предлагает `gh repo clone` в папку рядом с текущим проектом и открывает клон.

Статус CI в шапке после ветки: мягкая плашка `✓ CI` success, `✗ CI` error (жирная), `● CI` warning — запуски Actions
для коммита HEAD (не отправлен — плашки нет). В сеть: новый коммит — сразу, пока идёт — раз в 15 с по таймеру,
иначе не чаще раза в 2 минуты; ошибка сети не показывается. `ctrl+o` открывает упавший (или идущий) запуск в браузере.

Окно GitHub открывается прямо из обработчика клавиши: внутри `App.Invoke` вложенное окно не получило бы свои загрузки.

## Клавиши (глобальные)

| Клавиша       | Действие                    |
|---------------|-----------------------------|
| `1` `2` `3` `4` | перейти к панели (4 — stash, если не пуст) |
| `tab` / `shift+tab` | следующая / предыдущая панель |
| `↑↓` / `j k`  | навигация                   |
| `enter`       | открыть / зайти внутрь      |
| `esc`         | назад / отменить операцию   |
| `p` / `P` / `f` | pull / push / fetch       |
| `z`           | отменить последнее действие |
| `s`           | спрятать изменения в stash  |
| `A` / `C`     | прервать / продолжить merge / cherry-pick / rebase |
| `,`           | настройки                   |
| `T` / `L`     | сменить тему / язык (ru ↔ en) |
| `ctrl+p`, `:` | палитра команд              |
| `?`, `F1`    | справка: плашки, разделы, шапка, клавиши |
| `~`           | Command Log                 |
| `r`           | обновить                    |
| `q`           | выход                       |

Клавиши задаются командами (`AppCommand.Key` в `CommandRegistry`); справка строит из них раздел клавиш.
