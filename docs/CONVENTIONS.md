# Соглашения

## Код (C#)
- File-scoped namespace: `namespace EaseGit.Git;`
- Один публичный тип на файл, имя файла = имя типа.
- `PascalCase` для типов, методов и свойств; `_camelCase` для приватных полей; `camelCase` для локальных переменных.
- Асинхронные методы заканчиваются на `Async` и принимают `CancellationToken ct` последним параметром.
- Модели — `record` (неизменяемые). Классы по умолчанию `sealed`.
- `Nullable` включён: без `!` без причины.
- Никакого статического изменяемого состояния. Зависимости передаются через конструктор.
- Без «магических строк» для цветов и символов: всё берётся из `Theme`.
- Комментарии пишем, когда код не объясняет *почему*. Язык комментариев — русский.

## Работа с git
- git вызывается **только** через `GitRunner`.
- Аргументы только через `ArgumentList`, без склейки строк.
- Только машиночитаемый вывод: `--porcelain=v2`, `--format=...`, `-z`.
- Перед путями ставим `--`: `git add -- <path>`.
- Git не должен ничего спрашивать: `GIT_TERMINAL_PROMPT=0`, для коммита сообщение передаём через `-F -` (stdin).
- Опасные команды (`reset --hard`, `push --force`, `branch -D`, `restore`, `clean`) — только через `ConfirmDialog` с предпросмотром команды.

## Тесты
- Каждый парсер покрыт тестами на реальном выводе git (образцы в `EaseGit.Tests/Samples/`).
- Обязательные кейсы: пустой репозиторий, пути с пробелами, кириллица, rename, detached HEAD.
- Имена тестов: `Метод_Условие_Результат`, например `Parse_RenamedFile_ReturnsOldPath`.

## Тексты интерфейса
- Интерфейс на двух языках: каждая строка пишется парой `T("Коммит", "Commit")` прямо там, где показывается
  (`Localization/Loc.cs`, подключён глобально). Число со словом — `Plural(n, "файл", "файла", "файлов", "file", "files")`.
- Строки нельзя кэшировать в `static readonly` / `const`: язык меняется с перезапуском окна, используй свойство `=>`.
- Русский — язык по умолчанию: тесты проверяют русские тексты; тесты, меняющие язык, — в коллекции `LocTests`.
- Не переводим: служебные исключения для разработчика, ключевые слова палитры (`keywords`), команды git.
- С заглавной буквы только первое слово: «Новая ветка», а не «Новая Ветка».
- В подсказках внизу без точек: `c коммит · p pull`.
- Ошибка = что случилось + что делать: «Нет upstream для main. Нажми P ещё раз, чтобы выполнить push -u origin main».
- Термины git (stage, commit, push, merge) не переводим, если перевод хуже понятен.

## Git самого проекта
- Ветки: `feature/<кратко>`, `fix/<кратко>`, `docs/<кратко>`.
- Коммиты: [Conventional Commits](https://www.conventionalcommits.org/ru/) — `feat: панель diff`, `fix: парсинг rename`, `docs: план`.
- `main` всегда собирается и проходит тесты.
- Одна задача из [PLAN.md](PLAN.md) — одна ветка, после merge отмечаем `[x]`.
